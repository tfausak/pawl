# Meld Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hanweir Battlements melds with Hanweir Garrison into Hanweir, the
Writhing Township -- one permanent represented by two cards -- and puts two cards
into the graveyard when it dies.

**Architecture:** A `Layout.Meld` arm classifies the two printed halves as meld
cards. A `Source.OfMeld` arm says one object is represented by several cards, with
the combined face interned from an `Effect.Meld` payload the way a token's card is
interned. `Pawl.Engine.Event`'s returning zone-change doors widen from one
arriving id to a sequence, which is what lets one permanent leave the battlefield
and two cards arrive.

**Tech Stack:** Haskell, cabal, tasty via `Pawl.Spec`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-27-meld-design.md` -- read it first; this
plan argues from it.

## Global Constraints

- Branch `369-meld`, already created, spec already committed. Never commit to
  `main`; Taylor merges.
- `CLAUDE.md` governs: `docs/rules.txt` is the only rules ground truth, grepped by
  rule number; comments and PR body stay terse; an elision gets an issue and a
  code-site citation naming only what is not implemented.
- The rules core must not case on an effect's IDENTITY. Casing on `Layout`,
  `Source` and `Keyword` is fine -- those are rulebook classifications.
- Suite: `cabal test --test-options '--timeout 15s --hide-successes'`, redirected
  to a file and read from the file. While iterating add `-p Meld`. Full suite
  before every commit.
- Copy `cabal.project.local` in from the primary checkout as a bare command
  before the first build if working in a fresh worktree.
- Enumerate every edit site by grepping a sibling constructor BEFORE rebuilding;
  do not let `-Werror` name them one build at a time.
- Every constructor list this plan touches has known blind spots `-Werror` will
  not name: `Pawl.Engine.Event`'s `eventBindings` fallthrough, `Pawl.Engine.Filter`'s
  `boundSlots`, `Pawl.ZoneTriggerSpec`'s `everyTriggerCondition` and
  `representativeEvents`, and `Pawl.CardSpec`'s filter and keyword traversals.
  Read each and say in the PR why it is right.
- Card facts, verified on Scryfall 2026-08-27, are in the spec. Do not re-derive
  them from memory; re-fetch with
  `curl -s 'https://api.scryfall.com/cards/named?fuzzy=<name>'` if in doubt.

3. Interns the result card: `State.state (Game.intern (Printing.MkPrinting card))`,

4. Puts ONE new object onto the battlefield through the same entry path a token
   takes (`Pawl.Engine.Event.placeObject` plus the entry loop `createTokens`
   runs), with `Source.OfMeld` naming the interned result and the components'
   printings in the order the objects were named, owner and controller the shared
   owner. CR 712.14c: they "enter the battlefield as a single permanent", so the
   entry replacement loop and the enters-the-battlefield trigger scan must both
   see it.
5. Removes the component objects from exile -- they are not two objects any more.
