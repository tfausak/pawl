# M4.5 P3a — Color (layer 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make an object's color a projected CR 613 layer-5 characteristic — derived from mana cost, color indicator and devoid, changed by one `Modification`, and read by three closed-half subsystems (targeting, the layer fold, blocking).

**Architecture:** `ProjectedCharacteristics` grows a `colors :: Set Color` field seeded by `Projection.baseCharacteristics` from the card (CR 202.2 mana cost ∪ CR 204.2 color indicator, emptied by CR 702.114a devoid) and overwritten in layer 5 by `Modification.SetColor`. Three readers consume it: `TargetSpec.NonblackCreatureTarget` (Doom Blade), `Affected.CreaturesOfColor` (Bad Moon), and `Keyword.Fear` in `Combat` (Aphotic Wisps). No new opcode, no new prompt, no change to `Object`, `GameState`, or the event pipeline.

**Tech Stack:** Haskell 2010 (GHC 9.14.1 from the Nix flake), `tasty` + `tasty-hunit`, the hand-rolled `Pawl.Json`/`Pawl.Codec` card codec.

**Spec:** `docs/superpowers/specs/2026-07-20-p3a-color-design.md`. Read §2 before Task 1 and §7 before Task 9.

```haskell
-- CR 202.2 / 204.2: an object's PRINTED colours -- the colours of the coloured
-- mana symbols in its mana cost, together with the colours its colour indicator
-- denotes. CR 202.2b: an object with no coloured mana symbols and no indicator is

baseColorsOf :: Card.Type.Card -> Set Color.Color
baseColorsOf card =
  Set.union
    (Card.Type.colorIndicator card)
    (manaCostColors (Card.Type.manaCost card))

-- CR 202.1: a land has no mana cost at all, so it contributes no colours.
manaCostColors :: Maybe ManaCost.ManaCost -> Set Color.Color
manaCostColors mc = case mc of
  Nothing -> Set.empty
  Just (ManaCost.MkManaCost symbols) -> Set.fromList (Maybe.mapMaybe symbolColor symbols)

-- CR 202.2a: only a coloured mana symbol carries a colour. Generic ({2}), {X},
-- and the colourless symbol ({C}) carry none -- {C} is colourless mana, and
-- CR 105.2c says colourless is not a colour.
symbolColor :: ManaSymbol.ManaSymbol -> Maybe Color.Color
symbolColor symbol = case symbol of
  ManaSymbol.OfType (ManaType.Colored c) -> Just c
  ManaSymbol.OfType ManaType.Colorless -> Nothing
  ManaSymbol.Generic _ -> Nothing
  ManaSymbol.Variable -> Nothing
```

```haskell
-- CR 702.36b: a creature with fear can't be blocked except by artifact creatures
-- and/or black creatures.
--
-- The same asymmetry as flying (see evasionAllows): fear restricts being BLOCKED,
-- never blocking, so the question is asked of the ATTACKER first. Both halves of
-- the exception read the PROJECTION -- a creature made black by a CR 613 layer-5
-- effect blocks legally, and a devoid creature with a black mana cost does not.
fearAllows :: ObjectId -> ObjectId -> GameState -> Bool
fearAllows blocker attacker gs =
  not (Projection.hasKeyword Keyword.Fear attacker gs)
    || Set.member CardType.Artifact (Projection.cardTypesOf blocker gs)
    || Set.member Color.Black (Projection.colorsOf blocker gs)
```

In `legalBlockDeclaration`, extend the `ok` conjunction — CR 509.1b makes restrictions cumulative:

```haskell

        wellFormed blocker attacker
          && evasionAllows blocker attacker gs
          && fearAllows blocker attacker gs
```

## Self-review notes for the executing engineer

Three things this plan deliberately does **not** do, so you don't "fix" them:

1. **No `AddColor` constructor.** CR 105.3's "in addition to its other colors" clause has no card in the pool. Adding an unexercised constructor breaks the no-constructor-without-a-card discipline (design.md §4). It is a named deferral in spec §7.
2. **No CR 613.3 CDA-precedence key on `Gathered`.** Devoid is applied at the projection seed instead, and the code comment in `baseColorsOf` argues the observable equivalence from four cases. If you find a fifth case where the two orderings differ, **stop and say so** — that is a plan bug, not a coding decision.
3. **No self-slot and no `ModifySelf` opcode.** This is why the devoid creature is a labeled synthetic. If you are tempted to add one so Slaughter Drone becomes encodable, that is a different phase's work; the expiry is already recorded.

One thing to watch: `data/cards/*.json` files are **byte-compared** by `CardsSpec.checkFile` against `Json.render`'s output. If a byte assertion fails, the JSON in this plan is in the wrong key order for your build — fix the file to match the renderer, never the assertion.
