# M5.6b — Setup: mulligans, the first draw, restart, subgames Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make pawl's three *setup* paths multiplayer-correct — the free first mulligan (CR 103.5c / CR 800.6), the starting player's first draw (CR 103.8c / CR 800.7), and the two paths that rebuild a game in place, restart (CR 727.1) and subgames (CR 729.2), which today revive a player who has already left.

**Architecture:** Two capability seams and one shared filter. Each multiplayer-only *capability* is derived through exactly one named function whose name states the capability rather than its cause — `Mulligan.freeMulligans :: GameState -> Natural` (subtracted from the bottom count) and `Engine.skipsDraw :: GameState -> Bool` (consumed by one `Monad.unless`) — with the seat-count test *inside* the function, so a later format layer redefines the function and touches no call site. No options record, no `Variant` type, no `GameState` field: nothing reads one yet. Both functions read `GameState.turnOrder`, the permanent seating roster M5.6a committed to, which is what makes them answer CR 800.1's "begins with more than two players" rather than "currently has." The rebuild paths get one shared `Departure.stillPlayingInOrder :: GameState -> [PlayerId]` (the still-playing set intersected with the seating order, because CR 103.5's mulligan declarations go around the table in turn order) plus one shared `Setup.resetPlayers`, which resets the players who are in the game and leaves a departed player's `Status` alone.

**Tech Stack:** Haskell 2010 (GHC 9.14.1), `tasty`/`tasty-hunit`, the `StateT GameState (Program Prompt)` suspension monad.

```haskell
-- CR 800.1: the three-seat twin of libraryGame -- n Mountains in each of the
-- three players' libraries, nothing elsewhere. The SEAT COUNT is what CR 103.5c
-- reads (through Mulligan.freeMulligans), so this must be built from
-- S.threePlayers: a two-seat game with a third player's cards in it is not a
-- multiplayer game.
libraryGame3 :: Printing.Printing -> Int -> GameState.GameState
libraryGame3 mountain n =
  let g0 = Setup.emptyGame S.threePlayers
      addMany pid g = List.foldl' (\h _ -> snd (S.addCreature mountain pid h)) g (replicate n ())
   in poolToLibrary S.carol (poolToLibrary S.bob (poolToLibrary S.alice (addMany S.carol (addMany S.bob (addMany S.alice g0)))))

-- run, for three seats. CR 103.5: the declaration order is the turn order, so
-- the list is [alice, bob, carol] and not a set.
run3 :: (forall r. Prompt.Prompt r -> r) -> GameState.GameState -> GameState.GameState
run3 answer gs = snd (Engine.runGamePure answer gs (Mulligan.openingHands [S.alice, S.bob, S.carol]))

-- Always mulligan, recording every player asked. How many times a player is
-- ASKED is how pawl expresses CR 103.5's limit ("A player can take mulligans
-- until their opening hand would be zero cards, after which they may not take
-- further mulligans"): a hand of zero is a forced keep and is never asked. So
-- counting asks is how CR 103.5c's second clause -- the free mulligan does not
-- count toward the number of mulligans a player may take -- becomes observable.
recordAlwaysMulligan :: Prompt.Prompt r -> State.State [PlayerId] r
recordAlwaysMulligan p = case p of
  Prompt.DeclareMulligan _ pid _ -> do
    State.modify' (pid :)
    pure MulliganDecision.Mulligan
  _ -> pure (S.identityAnswer p)
```
