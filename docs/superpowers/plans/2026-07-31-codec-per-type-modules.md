# Codec Per-Type Modules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 2,377-line `Pawl.Codec.All` monolith with 95 `Pawl.Codec.<TypeName>` modules, one per type, closing #481.

**Architecture:** The codec's two mutually-recursive clusters are self-inflicted: seven types are parametric (`data Effect card`, `data Count quantity`) precisely to keep `Pawl.Types.*` acyclic, and the codec throws that away by monomorphizing (`effectToJson :: Effect Card -> Value`). Restoring the parametricity — passing a sub-codec as an argument — makes the codec module graph isomorphic to the type module graph, which is a verified 17-layer DAG. No `hs-boot`, no cluster modules. The parametric change lands first, in place, so that a regression has exactly one candidate cause before any file moves.

**Tech Stack:** GHC 9.14.1 via the Nix flake, `cabal`, `tasty` (`cabal test`), `hooky` (ormolu + hlint + cabal-gild).

## Global Constraints

- `cabal build all` must be warning-free — build `all`, never just the library; the suites break separately.
- **One build at a time.** Never run two builds or a build and a test concurrently.
- `hooky fix` then `hooky run`, both on **staged** files: `git add` first, and stage again after `fix` reformats.
- Adding or deleting a module requires `cabal-gild pawl.cabal` run **directly** — `hooky fix` only acts on staged files and will skip it.
- Never hand-edit an `exposed-modules` field; it is generated by the `-- cabal-gild: discover` directive.
- Imports alias to the last component (`import qualified Pawl.Codec.Card as Card`).
- No unchecked numeric conversions: `fromIntegral`, `fromInteger`, `realToFrac`, `toEnum` are banned by `.hlint.yaml`.
- This refactor changes **no JSON bytes**. Any diff in `data/cards/*.json` round-tripping is a bug, not an expected outcome.
- Work on the existing branch `2026-07-30-more-sublibraries`. Do not cut a new one.

## File Structure

| Path | Responsibility |
|---|---|
| `source/libraries/codec/Pawl/Codec/Json.hs` | Generic `Value` combinators only — nothing that names a `Pawl.Types` type |
| `source/libraries/codec/Pawl/Codec/<TypeName>.hs` × 95 | The `<typeName>ToJson` / `jsonTo<TypeName>` pair for one type, plus helpers built from it |
| `source/libraries/codec/Pawl/Codec/All.hs` | Deleted in Task 8 |
| `source/libraries/registry/Pawl/Registry.hs` | Repointed to `Pawl.Codec.Card` |
| `source/test-suite/Pawl/{CodecSpec,CardsSpec,CardSpec}.hs` | Repointed to the per-type modules they use |

**The placement rule for helpers:** a helper lives in `Pawl.Codec.Json` if it touches only `Value` and type variables. If it names any `Pawl.Types` type or calls any per-type codec, it lives with the type it is built from. Violating this inverts the layering and reintroduces the cycle this plan exists to remove.

**Dependency layers** (from the `Pawl.Types` import graph; a module may only import ones in a lower layer):

- **L0 (38):** AbilityName, Aggregation, BeginningStep, CardType, CastingPermission, Color, CombatStep, Comparison, ControllerRelation, Counterability, DamageKind, DamageRewrite, DestructionRewrite, DiscardCause, EndingStep, ExtraPhase, ModeIndex, ModeSelection, MonarchTarget, ObjectId, Optionality, PlayerCounterKind, PlayerId, PlayerRelation, PlayerScope, Pool, Regenerability, Scaling, SearchDestination, SlotName, Subtype, Supertype, TapState, TriggerFrequency, TurnScope, Uses, Zone, ZoneChangeSubject
- **L1 (12):** DamagePattern, EventShape, Filter, ManaType, Phase, PlayerRef, Recipient, TokenEntry, TokenPattern, TypeLine, ZoneChange, ZoneChangePattern
- **L2 (11):** ActivationTiming, Affected, CastingRestriction, CostComponent, DamageEvent, ManaProduction, ManaSymbol, ObjectRef, PhaseSelector, Scope, TargetSpec
- **L3 (5):** AttackRequirement, BlockRequirement, Count, ManaCost, PhasePattern
- **L4 (3):** Cost, PlayerEffect, Quantity
- **L5 (5):** Condition, Keyword, PlayerStaticAbility, Power, Toughness
- **L6 (6):** CounterKind, Duration, EntryOption, Expiry, Modification, TriggerCondition
- **L7 (3):** CounterPattern, EntryRewrite, StaticAbility
- **L8 (1):** ReplacementEffect
- **L9–L13 (6):** Effect → Mode → Modal → {ActivatedAbility, TriggeredAbility} → Card
- **L14–L16 (5):** Printing, ProjectedCharacteristics → Binding, GameEvent → DelayedTrigger

### Task 1: Restore parametricity in place

Fourteen functions currently monomorphize seven parametric types. Change them **inside `All.hs`**, with no file moves, so the suite proves the semantic change alone.

**Files:**
- Modify: `source/libraries/codec/Pawl/Codec/All.hs` (lines 740, 746, 770, 774, 1626, 1690, 1890, 1922, 1974, 1986, 2173, 2186, 2194, 2201 and their call sites)
- Test: `source/test-suite/Pawl/CodecSpec.hs`

**Interfaces:**
- Produces: the fourteen signatures below. Every later task depends on these exact shapes.

```haskell
aggregationToJson      :: (q -> Value) -> Aggregation.Aggregation q -> Value
jsonToAggregation      :: (Value -> Either Text q) -> Value -> Either Text (Aggregation.Aggregation q)
countToJson            :: (q -> Value) -> Count.Type.Count q -> Value
jsonToCount            :: (Value -> Either Text q) -> Value -> Either Text (Count.Type.Count q)
effectToJson           :: (card -> Value) -> Effect.Effect card -> Value
jsonToEffect           :: (Value -> Either Text card) -> Value -> Either Text (Effect.Effect card)
modeToJson             :: (card -> Value) -> Mode.Mode card -> Value
jsonToMode             :: (Value -> Either Text card) -> Value -> Either Text (Mode.Mode card)
modalToJson            :: (card -> Value) -> Modal.Modal card -> Value
jsonToModal            :: (Value -> Either Text card) -> Value -> Either Text (Modal.Modal card)
activatedAbilityToJson :: (card -> Value) -> ActivatedAbility.ActivatedAbility card -> Value
jsonToActivatedAbility :: (Value -> Either Text card) -> Value -> Either Text (ActivatedAbility.ActivatedAbility card)
triggeredAbilityToJson :: (card -> Value) -> TriggeredAbility.TriggeredAbility card -> Value
jsonToTriggeredAbility :: (Value -> Either Text card) -> Value -> Either Text (TriggeredAbility.TriggeredAbility card)
```

- [ ] **Step 1: Write the failing test**

Add to the `Codec` group in `source/test-suite/Pawl/CodecSpec.hs`. This is a genuine new property, not a restatement of the refactor: it proves `effectToJson` reaches its `card` payload *only* through the supplied codec, which is exactly the claim that makes the split acyclic. `Effect.CreateEmblem` is chosen because it carries a bare `card` and nothing else.

```haskell
HU.testCase "effectToJson reaches card only through the supplied codec" $
  HU.assertEqual
    "emblem payload comes from the argument"
    (Codec.effectToJson (const (Json.jText (Text.pack "SENTINEL"))) (Effect.CreateEmblem ()))
    (Codec.effectToJson (const (Json.jText (Text.pack "SENTINEL"))) (Effect.CreateEmblem "a different card type entirely")),
```

- [ ] **Step 2: Run it and confirm it fails**

Run: `cabal test 2>&1 | tail -20`
Expected: a **compile** failure, not an assertion failure — `Effect.CreateEmblem ()` cannot typecheck against `effectToJson :: Effect Card -> Value`. That compile error is the red state.

- [ ] **Step 3: Change the fourteen signatures**

For each function, add the sub-codec parameter and thread it through recursive positions. Encoders take `(card -> Value)`; decoders take `(Value -> Either Text card)`. Within a function, recursive calls on nested `Effect card` / `Mode card` pass the same parameter straight down. Name the parameter `codec` on encoders and `decode` on decoders throughout, so the 14 read alike.

- [ ] **Step 4: Update the call sites**

Four functions instantiate the parametric codecs. Apply them to the concrete codec:

```haskell
-- in quantityToJson / jsonToQuantity (the Count arm):
Quantity.Count c -> countToJson quantityToJson c
("Count", _)     -> Quantity.Count <$> jsonToCount jsonToQuantity value

-- in countToJson / jsonToCount (the Aggregation field):
aggregationToJson quantityToJson a
jsonToAggregation jsonToQuantity a

-- in cardToJson / jsonToCard, projectedCharacteristics, delayedAbilities,
-- and delayedTrigger: pass cardToJson / jsonToCard down.
modalToJson cardToJson (CardT.spell c)
listTo (activatedAbilityToJson cardToJson) (CardT.activatedAbilities c)
listTo (triggeredAbilityToJson cardToJson) (CardT.triggeredAbilities c)
seqTo (effectToJson cardToJson) (Mode.effects m)   -- inside modeToJson, via its own parameter
```

Beware the knot in `Pawl.Codec.Quantity`: `quantityToJson` is passed to `countToJson`, which is called *from* `quantityToJson`. That is ordinary self-reference within one module and compiles fine — do not try to break it.

Run: `cabal build all 2>&1 | grep -icE "warn|error"` → expect `0`
Run: `cabal test 2>&1 | grep -E "^All |FAIL"` → expect all tests passing, count ≥ 1990 (1989 before, plus the new case)

- [ ] **Step 6: Commit**

```bash
git add source/libraries/codec/Pawl/Codec/All.hs source/test-suite/Pawl/CodecSpec.hs
hooky fix && git add source/libraries/codec/Pawl/Codec/All.hs source/test-suite/Pawl/CodecSpec.hs && hooky run
```

- [ ] **Step 1: Extract one module as the template**

`Pawl.Codec.Color` is the simplest. The whole shape:

```haskell

module Pawl.Codec.Color where

import Data.Text (Text)
import qualified Data.Text as Text
import qualified Pawl.Codec.Json as Json
import Pawl.Json.Value (Value)
import qualified Pawl.Types.Color as Color

colorToJson :: Color.Color -> Value
colorToJson c = Json.nullary . Text.pack $ case c of
  Color.White -> "White"
  -- ... remaining arms moved verbatim

jsonToColor :: Value -> Either Text Color.Color
jsonToColor =
  Json.decodeNullary
    (Text.pack "Color")
    [ (Text.pack "White", Color.White)
      -- ... remaining rows moved verbatim
    ]
```

Move the function bodies **verbatim** — only the `Json.` qualification and the imports are new. Delete them from `All.hs` and add `import qualified Pawl.Codec.Color as Color` there.
