# M5.6e — Close-out — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the last three pieces of M5.6 and then close it. (1) The `Opponent` axis is *proved* correct at three seats rather than asserted — three tests, each shown to fail under a stated wrong implementation, plus the comment corrections that stop describing a free-for-all in two-player terms. (2) The two `PropertySpec` generalizations: the three-way mirror joins the universal-invariant matchups, and a three-seat lands-only game must **not** end on the first deck-out. (3) The close-out itself — four deferred findings decided, the spec's two mis-citations back-propagated, `docs/progress.md` and `docs/design.md` written, `CLAUDE.md`'s status bullet **replaced**, and the tracker tidied with #172 closed last.

**Architecture:** Nothing new is built. This phase's only production edits are comments; every behavioural change M5.6 needed landed in M5.6a–d. That shapes the whole plan and is the single biggest risk in it: **a test over already-correct behaviour proves nothing by passing.** So every test task below names the wrong implementation it discriminates *and* gives the one-line mutation that produces the RED, to be applied, observed, and thrown away — never committed.

The one place real design judgement is required is Task 4. `PropertySpec.universalInvariants` hard-codes `120` card-backed objects and `>= 120` minted ids, both of which are `2 × 60`. A third seat makes the deck total 180 — and CR 800.4a then makes the *conserved* count fall as players depart, because at three or more seats a departing player's objects leave the game outright (`Departure.continuesAfterDeparture`, CR 800.1). So the constant does not become 180; the invariant becomes *sixty cards per player still in the game, and the whole matchup when CR 800.4a never ran*. That is a strictly stronger invariant than the constant it replaces, and it is the one assertion in this phase with a genuine chance of finding a bug.

### The one rule this phase reads *against* the code, and what to write

**CR 800.4h is the rule pawl's "a departed active player performs no turn-based actions" reading has to answer to, and CR 800.4j does not say what three comments claim it says.** CR 800.4j is about **priority** — it says the turn continues without an active player, and then enumerates what happens *if the active player would receive priority*. It says nothing about turn-based actions. CR 800.4h is the clause that does speak to one of them: choosing the defending player is required by a *rule* (CR 507.1, CR 703.4h) of a player who has left, and CR 800.4h says the next player in turn order makes that choice. pawl skips the action instead. That divergence is real, it is unobservable, and Task 7 is where all three sites get told to say so. The unobservability argument, in full: CR 506.2's first sentence makes the attacking player the active player, and after CR 800.4a a departed player owns and controls nothing, so no creature can attack under any defending player CR 800.4h would install — the field would be written and never read. Untap (CR 703.4c) and the cleanup discard (CR 703.4n) are vacuous for the same reason; the draw (CR 703.4d) is not a choice at all, so CR 800.4h does not reach it.

## Task 1: Silence stops **both** opponents (CR 806.1, `PlayerScope.Opponents`)

**Files:**
- Modify: `source/test-suite/Pawl/PlayerEffectSpec.hs`

**Interfaces:**
- Produces: a group-local `threeSeatSilenceBoard` and one test case in `silenceTests`.
- Consumes: `S.threePlayers`, `S.addCreature`, `S.addHandCard`, `PlayerEffect.prohibitsCasting`, `Cast.castable` — all already imported by `PlayerEffectSpec`; check its import list and add only what is missing.

**Why the existing Silence coverage does not already do this.** `silenceTests` has five cases and every one runs on `silenceBoard`, which is `Setup.emptyGame S.bothPlayers`. The case named `CR 109.5 the Opponents scope spares the caster` asserts alice is not prohibited and bob is — which at two seats is the *same* assertion twice, because "the other player" and "every other player" agree. That is precisely the fixture-shape defect this milestone caught eight times, so the new case is not a duplicate: it is the first fixture where the two readings come apart.

**Why a new local board rather than parameterizing `silenceBoard`.** `silenceBoard` returns a five-tuple that five cases destructure, and widening it would touch all five for one new case. The new board needs less than it does (no land to play, no activated ability — those cases stay two-seat, and correctly so, since the ruling they encode is about *what* Silence stops, not *whom*), so a second, smaller local builder is cheaper and leaves the existing cases byte-identical.

- [x] **Step 1: Write the failing test**

Add next to `silenceBoard` in `source/test-suite/Pawl/PlayerEffectSpec.hs`:

```haskell
-- CR 800.1: the three-seat Silence board. alice has two Plains and a Silence in
-- hand; bob and carol each have a Mountain and a creature in hand to cast. The
-- SEAT COUNT is the whole point -- at two players "the other player" and "every
-- other player" are the same set, so silenceBoard cannot tell the readings apart.
threeSeatSilenceBoard :: Printing.Printing -> Printing.Printing -> Printing.Printing -> Printing.Printing -> (ObjectId.ObjectId, ObjectId.ObjectId, ObjectId.ObjectId, GameState.GameState)
threeSeatSilenceBoard plains silence mountain piker =
  let gs0 = Setup.emptyGame S.threePlayers
      (_, gs1) = S.addCreature plains S.alice gs0
      (_, gs2) = S.addCreature plains S.alice gs1
      (silenceId, gs3) = S.addHandCard silence S.alice gs2
      (_, gs4) = S.addCreature mountain S.bob gs3
      (bobsPiker, gs5) = S.addHandCard piker S.bob gs4
      (_, gs6) = S.addCreature mountain S.carol gs5
      (carolsPiker, gs7) = S.addHandCard piker S.carol gs6
   in ( silenceId,
        bobsPiker,
        carolsPiker,
        gs7 {GameState.phase = Phase.PrecombatMain, GameState.activePlayer = S.alice, GameState.priority = Just S.alice}
      )
```
