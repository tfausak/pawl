# Ante unit 2: ownership changes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land unit 2 of the ante spec: pile membership decoupled from `Object.owner` (CR 400.1, 400.3), the two ownership writes CR 407.3 allows (`SetOwner`, `ExchangeOwnership`), Darkpact's exchange of an ante card with the top of a library (CR 701.12a, 701.12d), a "from anywhere" object reference (CR 400.7), and "your graveyard" read off the pile a card left. Proved by Darkpact, Bronze Tablet, Tempest Efreet and Timmerian Fiends. It does not close #249; unit 3 (the payout and the report) remains.

**Architecture:** `Game.removeFromZones` loses its player argument and finds the pile by search (`Game.pileHolderOf`). Three open-half opcodes: `Effect.SetOwner` (payload `Pawl.Types.SetOwner`), `Effect.ExchangeOwnership` (`Pawl.Types.ExchangeOwnership`) and `Effect.ExchangeWithTopOfLibrary` (`Pawl.Types.ExchangeWithTopOfLibrary`), each interpreted only in `Pawl.Engine.Resolve.Effect`. Ownership is a write through one function, `Game.setOwner`, never a zone change and never an event. `ObjectRef.FromAnywhere` follows a slot's object through this turn's `Moved` log (`Game.currentIncarnation`). `LastKnown.pile` records the pile a departing card left, and `CardLeavesZone.whose` reads it in place of the `Filter.OwnedBy` conjunct six printings used for "your graveyard" or "your library". Darkpact's target needs `Pool.CardsInAnte`.

**Tech Stack:** Haskell (GHC via the repo's nix flake), cabal, tasty.
**Spec:** docs/superpowers/specs/2026-10-08-ante-design.md (its unit-2 section was corrected in the commit that adds this plan; the corrections are listed under "Divergences" below).

## Divergences from the spec (corrected in the spec in this plan's commit; the PR body repeats them)

1. **`LastKnown` alone records the pile, not `ZoneChange`.** Every departure reader (`Event.Binding.admitsDeparture`, CR 729.4a's `LeftTheGame` arm) reaches the departed id's CR 608.2h record already, and `ZoneChange` has 120 positional constructions.
2. **"Your graveyard" is a new `CardLeavesZone.whose` field.** Six printings move their `OwnedBy You` conjunct into it. Kithkin Brinefarer, Volatile Rift and Veteran Ghoulcaller keep `OwnedBy You` too: it reads "into your hand", an arrival, which CR 400.3 keeps exact.
3. **The Kishla pair needs the opponent's turn.** Kishla reads "during your turn", so an opponent's Kishla on the Efreet controller's turn never triggers under either reading.
4. **Bronze Tablet is two `SetOwner`s, not `ExchangeOwnership`.** "That player owns this card and you own the other exiled card" names two new owners. The ruling for a stolen Tablet (2004-10-04) is the case where an exchange gives the wrong answer.
5. **No `GameEvent.OwnerChanged`.** Nothing reads it. Unit 3's report, as the spec designs it, reads `Object.startingOwner` against `Object.owner`, and `GameState.events` is cleared every turn, so it could not carry a whole-game report. A new `GameEvent` constructor is about 135 arms in `Event.Match` alone.
6. **Darkpact needs `Pool.CardsInAnte` and `Effect.ExchangeWithTopOfLibrary`.** The spec named the exchange's semantics but no opcode. Two sequential instructions (ante the top card, then move the target to the library) break CR 701.12a when the library is empty.
7. **The Fiends board uses Leyline of the Void, not Rest in Peace.** Rest in Peace exiles the final put too, so the Fiends ends in exile whether or not "from anywhere" found it. Leyline, controlled by the artifact's owner, exiles only cards bound for that owner's opponents' graveyards.
8. **`Resolve/Effect`'s `sinkInLibrary` call stays.** It reads the library the card has just arrived in, which CR 400.3 makes the owner's.
9. **Subgame lineage.** An ownership change inside a subgame falsifies `Setup.funnelBack`'s "owner is invariant" reading for a departed former owner. Filed (Task 2) and cited beside #4829. The follow-the-card log here is not #4829's lineage: it is cleared every turn and never crosses a game boundary. #4829 stays as it is.

```haskell
-- CR 400.1: the player whose library, hand or graveyard holds this card -- its
-- owner (CR 400.3) except between an ownership change and the move that follows
-- it in one resolution (CR 407.3). Found by search for that reason; Nothing for
-- an object in no player's pile.
pileHolderOf :: ObjectId -> GameState -> Maybe PlayerId
pileHolderOf oid gs = Foldable.asum (fmap (pileHolderIn oid) [GameState.library gs, GameState.hand gs, GameState.graveyard gs])

-- The player whose pile in one per-player zone holds the id.
pileHolderIn :: ObjectId -> Map.Map PlayerId (Seq.Seq ObjectId) -> Maybe PlayerId
pileHolderIn oid piles = fmap fst (List.find (Foldable.elem oid . snd) (Map.toList piles))

removeFromZones :: ObjectId -> GameState -> GameState
removeFromZones oid gs =
  let -- CR 400.1: out of the pile that holds it, never Object.owner's, which an
      -- ownership change can have moved first.
      fromPile piles = case pileHolderIn oid piles of
        Just pid -> Map.adjust (Seq.filter (/= oid)) pid piles
        Nothing -> piles
   in gs
        { GameState.library = fromPile (GameState.library gs),
          GameState.hand = fromPile (GameState.hand gs),
          GameState.graveyard = fromPile (GameState.graveyard gs),
          -- (keep the battlefield, phasedOut, exile, command and ante lines,
          -- and the CR 702.26k comment, exactly as they are)
          GameState.attractionDecks = fromPile (GameState.attractionDecks gs),
          GameState.planarDecks = fromPile (GameState.planarDecks gs),
          GameState.schemeDecks = fromPile (GameState.schemeDecks gs),
          GameState.stack = filter (/= oid) (GameState.stack gs)
        }
```
