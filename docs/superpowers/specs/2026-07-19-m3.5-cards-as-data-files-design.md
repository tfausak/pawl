# M3.5 cards as data files — design

Design for milestone **M3.5**, the interstitial between M3 and M4 (numbered
`.5` so it does not renumber M4–M7, which are cited by number throughout — see
`docs/design.md` §3, M3.5). This milestone cashes **§2.7** ("cards are runtime
data, never Haskell modules"): it makes JSON the card representation and files
the source of truth. **Zero opcodes, zero rules.** It is a representation change
and a relocation, sequenced *before* M4 on purpose — proving the codec against
the two-dozen-card M3 pool is cheap, and every M4 opcode is then born
serializable instead of retrofitted across a growing pool.

The milestone's spine is one property, made progressively more load-bearing:

> **The honesty round-trip.** For every card, `jsonToCard . cardToJson ≡ Right`.

This is what §4 calls "keeps us honest": it proves the card model is fully
first-order data, and fails loudly the day a closure is smuggled into the card
model. §2.7's "never Haskell modules" becomes *enforceable* rather than
aspirational — and by the end of the milestone it is enforced by the **module
graph**, not just discipline: the engine library will no longer be able to name
a card.

This is a types-and-architecture spec, not an implementation plan.

## 0. The core idea and the phased spine

M3.5 has three movements, independent in what they touch:

| Movement | What it does | Touches |
|---|---|---|
| **The codec** | A hand-rolled JSON value type, a parser/renderer, and a `Card ⇆ Json` codec, with the round-trip property over the current card pool | New library modules only |
| **The relocation** | The ~30 hand-written card values leave the engine library; the library keeps only the card-*agnostic* classification functions | `Pawl.Card`, `Pawl.Setup`, test qualifiers |
| **Files as source of truth** | Every card is rendered to `data/cards/<slug>.json`, committed, and both non-engine consumers read *the files* — the benchmark by `IO`, the test suite by a Template Haskell shim | `data/cards/`, the benchmark, `Pawl.Cards` |

The end state:

- `data/cards/*.json` is **the** source of truth. The hand-written `MkCard {…}`
  literals are **deleted**, not mirrored.
- The **engine library** carries no card data — only classifications
  (`isLand`, `isPermanent`, …) and the card-agnostic codec.
- The **benchmark** `IO`-loads exactly the cards it references (the scalable
  path, proven end-to-end at runtime).
- The **test suite** compile-time-splices its fixtures from the same files (a
  bounded set, ~30, via a **temporary** TH shim with a named expiry).

### Why these means, matched to churn

"Files become the source of truth" for a *pure top-level binding*
(`mountainPrinting :: Printing`, used pervasively as a `Map` key, inside
`Source.OfCard`, and in pure `let`-fixtures across ~15 test files) can only be
satisfied three ways: hand-written Haskell (what we are leaving), compile-time
embedding (TH), or `unsafePerformIO` (banned). There is **no pure runtime file
read**. So the two non-engine consumers are converted by different means, each
the cheapest that fits:

- **Benchmark → true `IO` loading.** Its `main` is already `IO`; the refactor is
  small, and it is the **proof positive** that files → parse → real game works at
  runtime. It loads *only the specific files* its decks name (by slug), not the
  whole directory — no glob, no dependency on the full pool.
- **Test suite → TH shim.** A true `IO` conversion would churn ~15
  fixture-heavy files (every `combatBoardOf [Card.pikerPrinting …]`, every
  `Map`-keyed deck). The TH shim keeps those bindings pure and untouched by
  splicing them from the committed JSON at compile time. Only the bounded
  fixture set is ever TH-compiled — **the thousands-of-cards build-time problem
  never appears**, because bulk cards take the `IO` route the benchmark proves.

**TH is explicitly temporary.** A later milestone refactors the test suite to
`IO`-load like the benchmark and deletes the shim. This spec records that as a
named expiry (§7) so it cannot quietly become permanent.

## Goal and scope

**Exit criterion.** All of:

1. `Pawl.Json.parse` / `render` round-trip arbitrary JSON values (the ported
   scrod suite), and `render` is canonical (deterministic bytes for a given
   value).
2. `jsonToCard (cardToJson c) == Right c` for every `c` in the card pool, and
   the same through text: `jsonToCard =<< Pawl.Json.parse (Pawl.Json.render
   (cardToJson c)) == Right c`.
3. `data/cards/<slug>.json` exists for every card, is committed, and re-parses
   to exactly the compiled card (`jsonToCard <$> readFile ≡ Right c`), with
   re-rendering byte-stable against the committed file.
4. The engine library has **no** reference to any specific card. `Pawl.Card`
   exports classifications only; `Pawl.Setup` exports mechanism only.
5. The benchmark runs by `IO`-loading its cards from `data/cards/`, referencing
   no compiled card value.
6. The test suite's `Pawl.Cards` fixtures are TH-spliced from `data/cards/`; the
   hand-written `MkCard` literals no longer exist.

**Explicitly out of scope** (deferred, named where they land):

- **An engine-shipped card database or any runtime card loading in the library.**
  "Runtime" is the test suite and the benchmark. The engine loads nothing.
- **Directly authoring cards as JSON.** Cards are still authored as Haskell
  (rendered to files) this milestone; direct JSON authoring arrives with the M6
  transpiler. M3.5 only proves the *representation* and the *consumption path*.
- **`Printing` metadata (§2.8).** `Printing` is today a trivial `{card}` wrapper;
  the codec works at `Card` granularity and the file is per-card. When `Printing`
  grows artist/art/expansion (§2.8), the file format extends additively.
- **The test suite's true `IO` conversion.** The TH shim bridges it; the
  conversion (and TH deletion) is a later milestone (§7).
- **MTGJSON as a parse target.** The parser only ever reads JSON pawl itself
  wrote. It need not survive adversarial input, only well-formed pawl output.
  (The `_scratch/AllPrintings.json` round-trip oracle of §4 is a *separate*,
  later concern — the round-trip against MTGJSON `text`, not this JSON codec.)

## 1. The JSON primitive layer (the scrod port)

Lift-and-shift from `_scratch/scrod` (`prefer-boot-libraries`: a hand-rolled
parser needs zero *new* boot deps; `parsec` and `bytestring` are GHC boot
libraries). Port the *algorithms* near-verbatim; reconcile to pawl's rules.

### `Pawl.Type.Decimal`

scrod's `Decimal` verbatim — a mantissa/exponent pair carrying JSON numbers
without `Rational` and without the barred `Double` (§2.12: arbitrary-precision
only). One type, `Mk`-constructor, derives `Eq`, `Ord`, `Show`.

### `Pawl.Type.Json` — the value

One type per pawl's module rule. **Flatten scrod's seven-newtype split
(`Null`/`Boolean`/`Number`/`String`/`Array`/`Object`/`Pair`) into a single sum**
— that flattening is the "reconcile residual gaps" the M3.5 notes allow, and it
is more pawl-idiomatic than seven wrapper modules:

```haskell
data Value
  = Null
  | Boolean Bool
  | Number Decimal
  | String Text
  | Array [Value]
  | Object [(Text, Value)]   -- ordered assoc list: render is canonical by construction
```

`Object` is an ordered assoc list, not a `Map`: the codec controls key order, so
canonical render (exit criterion 1, 3) falls out of emitting fields in a fixed
order rather than relying on `Map`'s sort. Derives `Eq`, `Show` (and `Ord` if a
consumer needs it).

### `Pawl.Json` — parse and render

- `parse :: Text -> Either Text Value` — scrod's `decode`, with the stream
  **monomorphized to `Text`** (drops `FlexibleContexts`; `parsec` ships a `Text`
  `Stream` instance). A `Left` is a loud, total failure — never a partial crash.
- `render :: Value -> Text` — scrod's `encode` (a `bytestring` `Builder`),
  UTF-8-decoded to `Text` at the boundary. Deterministic.

Drop scrod's inline `spec` functions (pawl tests live in the test suite, §8) and
the `TemplateHaskellQuotes`/`Scrod.Spec` machinery they needed. The tiny
`Scrod.Extra.{Parsec,Builder}` helpers (`blank`, `parseString`, `toString`) fold
into `Pawl.Json` or a small helper as needed. **The primitive layer stays
Haskell 2010, no extensions.**

New library boot deps: `parsec`, `bytestring`.

## 2. The codec — `Pawl.Codec`

Free **functions and values, no type classes** (the codebase-wide decision:
codecs are values, not instances — which also avoids `FlexibleInstances` for
`[a]`/`Maybe a`). `Pawl.Codec` is the **sole authority** for `Card ⇆ Json`,
mirroring `Pawl.Resolve` (the sole `case`-on-`Effect` home) and `Pawl.Event`
(the sole replacement/trigger home). Every `Pawl.Type.*` module stays JSON-free.

Top-level pair:

```haskell
cardToJson :: Card -> Json.Value
jsonToCard :: Json.Value -> Either Text Card
```

plus an `xToJson` / `jsonToX` pair for each type in the **transitive closure of
`Card`'s fields** — `TypeLine` (→ `Supertype`, `CardType`, `Subtype`),
`ManaCost` (→ `ManaSymbol`), `Power`, `Toughness`, `Keyword`, `StaticAbility`,
`Effect` (→ `Quantity`, `SlotName`, `ManaType`, `CardCriterion`, `Modification`,
`Recipient`, `Duration`, `Layer`, `Affected`, …), `ActivatedAbility` (→
`AbilityCost`, `AdditionalCost`), `ReplacementEffect` (→ `ZoneChange`, `Zone`),
`TriggeredAbility` (→ `TriggerCondition`), `CastingPermission`, `TargetSpec`.
This ~30–40-type closure is the bulk of the milestone's mechanical work; the
plan enumerates it exhaustively and TDDs each pair.

The single starting module may split into `Pawl.Codec.*` sub-modules later if it
grows painful; start flat.

### The tagged-sum discipline — the §2.12 trap

The central risk of card serialization: **P/T and mana are not `Int`** (§2.12).
`power` of `*` is not a JSON number. Every sum type serializes as a **tagged
object** (scrod's `tagged` shape):

```json
{"type": "Literal", "value": 5}      // Quantity.Literal 5
{"type": "ManaValue"}                 // Quantity.ManaValue — nullary, no "value"
```

`Quantity` (and `Power`/`Toughness`, newtypes that delegate to it), `CardType`,
`Subtype`, `Supertype`, `Keyword`, `ManaSymbol`, `Effect` and every other sum go
through this shape. **Only genuine cardinals** (mana-symbol counts, `Literal`
payloads, list lengths)
become bare JSON numbers, decoded through `Decimal` → `Integer`. **No `Double`,
ever** — the type does not admit one. A round-trip that silently coerced `*` to a
number would fail exit criterion 2 loudly, which is the point.

### Decode errors, null policy, granularity

- **Errors:** `Either Text`, the message naming the offending field/constructor.
  It can grow to a structured path-aware error later; `Text` suffices now
  because decode only reads pawl's own output and a `Left` is a build/test
  failure, not a user-facing diagnostic.
- **Null / absence:** a `Maybe` field renders as `Null` (or is omitted); decode
  accepts missing-or-`Null` as `Nothing`. Empty `[]`/`Set` render as `Array []`.
  Every decoder is total — no partial matches, no `head`.
- **Granularity:** the codec is at `Card` level (the atomic characteristics,
  §2.8). `Printing` is the trivial wrapper; files are per-card, and a loader
  wraps `Card` → `Printing`. Encoding `Printing` directly is deferred with its
  metadata (§2.8).

## 3. The honesty round-trip (the properties)

Over the **whole card pool**, in the test suite:

- **P1 — value round-trip (the headline):** `jsonToCard (cardToJson c) == Right c`.
- **P2 — through text:** `jsonToCard =<< Pawl.Json.parse (Pawl.Json.render
  (cardToJson c)) == Right c`. Exercises the primitive layer end-to-end.
- **P3 — files & byte-stability (movement 3):** each committed
  `data/cards/<slug>.json` re-parses to its compiled card, and re-rendering that
  card equals the committed bytes (so files never churn on a no-op rebuild).

P1/P2 land with the codec (movement 1) over the *library's current*
`allPrintings`. P3 lands once the files exist (movement 3), and it is the
invariant that makes deleting the hand-written literals safe.

## 4. The relocation — the engine library goes card-free

Today `Pawl.Card` mixes two things: card-*agnostic* **classifications**
(`isLand`, `isCreature`, `isInstant`, `isPermanentType`, `isPermanent` — CR
110.1 / 305.6 closed-half logic, read by `Action`, `Cast`, `Stack`) and the ~30
hand-written **card values** + `allPrintings`. Split them along the
closed/open-half line:

- **`Pawl.Card` (library) keeps classifications only.** `Action`/`Cast`/`Stack`
  imports are unchanged (they already use only `isLand`/`isPermanent`/
  `isInstant`).
- **The card values + `allPrintings` move to the test suite** as `Pawl.Cards`
  (plural — distinct from the library's classification-only `Pawl.Card`; the
  name is cheap to change later).
- **`Pawl.Setup` (library) keeps mechanism only** — `emptyGame`, `newGame`,
  `createCard`, `createDeck`, `mirror`, `deckSize`. The concrete decks
  `redDeck`/`greenDeck`/`blackDeck` (built from card values) move out to the
  consumers that use them.
- Test files that referenced `Card.mountainPrinting` &c. switch the qualifier to
  `Cards.` (mechanical; a file using both classifications and data aliases them
  distinctly).

**After this, the engine library cannot name a card** — the §1 invariant (closed
half never depends on a card's identity) expressed in the module graph and
enforced by the compiler, not by discipline. The `_scratch/*` prior-art engines
all failed this at the *code* level; pawl gets it at the *build* level.

Sequencing note (the plan owns exact order): the benchmark must stop referencing
`Setup.redDeck` (movement 3) **before** the decks leave the library, so nothing
breaks mid-relocation.

## 5. Files as source of truth

### `data/cards/<slug>.json`

One file per card at the repo root under `data/cards/`. **Slug:** the card name,
lowercased, whitespace and `//` → `-`, punctuation stripped (`evolvingWilds` →
`evolving-wilds`). Names are unique in the pool — a test asserts slug uniqueness
so a future collision is loud. Files are generated by rendering the compiled
cards (`Pawl.Json.render . cardToJson`) and committed.

### Benchmark — `IO` loading (the proof)

`source/benchmark/Main.hs` becomes an `IO` program that, at startup, reads the
**specific** files for the cards its decks name (by slug), parses each via
`Pawl.Json.parse` + `Pawl.Codec.jsonToCard`, and builds its decks by name
lookup. It references **no compiled card value** and **does not** enumerate the
directory — it loads only what it cares about. A missing/malformed file fails
loudly at startup (`IO` failure, not `error` in pure code). This is the template
the test suite follows later.

The deck *recipe* (slug → count) is small and may be duplicated into the
benchmark rather than shared through a module (sharing would require a common
component — precisely the non-scalable compiled-card component rejected in
design). Keeping the real recipe by name-lookup keeps the benchmark
representative (goldfish/cast/fight over real Pikers and Bolts).

### Test suite — the TH shim (temporary)

`Pawl.Cards` (test suite) defines its named fixtures by **compile-time splice**
from the committed JSON:

```haskell
mountainPrinting = $(loadPrinting "mountain")   -- reads data/cards/mountain.json at compile time
```

`loadPrinting :: String -> Q Exp` (a small test-suite TH helper) `runIO`-reads
the file, registers `addDependentFile` (so edits force a rebuild), parses via
`Pawl.Codec.jsonToCard`, `fail`s the build on a `Left` (compile-time validation,
loud), and lifts the resulting `Printing` into the splice. `Lift` for `Card` and
its `Map`/`Set` fields is a mechanical concern the plan handles (deriving plus a
small hand-written lifting where `containers` lacks an instance). Extensions
(`TemplateHaskell`, `DeriveLift`) are scoped to the **test suite**, sanctioned as
the temporary shim.

The hand-written `MkCard {…}` literals are **deleted** in this movement — the
JSON files are now their only source. `allPrintings` becomes the list of
TH-spliced bindings. `redDeck`/`greenDeck`/`blackDeck` live here (or in
`Pawl.Support`) as fixtures over the spliced cards.

## 6. The phased spine

One milestone, one spec, one plan; the plan owns the decomposition into small
complete commits. Rough order (each a warning-clean, test-passing commit):

1. **Primitive layer** — `Pawl.Type.Decimal`, `Pawl.Type.Json`, `Pawl.Json`
   (ported), with the parse/render suite. Adds `parsec`, `bytestring`.
2. **The codec** — `Pawl.Codec` over the type closure, with P1 + P2 over the
   library's current `allPrintings`.
3. **Generate & commit files** — render every card to `data/cards/*.json`; add
   P3 (files re-parse to compiled cards) and the byte-stability + slug-uniqueness
   tests.
4. **Benchmark → `IO`** — refactor `Main.hs` to load its named cards from the
   files; it no longer touches `Setup.redDeck`.
5. **Relocate** — card values + decks leave the library for `Pawl.Cards`;
   `Pawl.Card` → classifications only; `Pawl.Setup` → mechanism only; qualifier
   renames.
6. **TH flip** — `Pawl.Cards` bindings become splices from the committed JSON;
   delete the hand-written literals.

Movements 1–3 are self-contained (new modules + a test); 4–6 are the relocation
and are independent of each other only in the order §4's sequencing note fixes.

## 7. Invariants preserved, and the expiries opened

**Preserved:**

- **The §1 invariant is strengthened, not touched.** The codec `case`s on effect
  *identity* freely — but `Pawl.Codec` is open-half machinery (serialization of
  the card AST), not the rules core, exactly as `Pawl.Resolve` may `case` on
  `Effect`. The closed half gains no new `case`; it *loses* its ability to name a
  card at all (§4).
- **No new opcode, no new rule, no elided prompt.** Nothing in the engine loop
  changes. `GameState`, resolution, priority, projection are untouched.
- **Purity.** The engine library reads no files and gains no `IO`. All file
  reading is in the benchmark (`IO`) and the test suite (compile-time `runIO` in
  the shim).
- **No partial functions.** Decode is total (`Either`); the TH helper `fail`s in
  `Q`, never in the spliced value.

**Expiries opened (each names the milestone that kills it):**

- **The TH shim is temporary.** A later milestone (post-M3.5, when the test
  suite's `IO` conversion is worth its churn) refactors `Pawl.Cards` to `IO`-load
  like the benchmark and deletes `TemplateHaskell`/`DeriveLift`. Recorded here so
  it cannot become load-bearing silently.
- **`Either Text` decode errors** may graduate to a structured path-aware error
  when a consumer needs to locate a failure in a large file (M6 transpiler
  output).
- **`Card`-granularity codec** extends to a `Printing`-granularity one when
  `Printing` grows metadata (§2.8).
- **The benchmark's duplicated deck recipe** collapses if a shared,
  non-compiled card-loading utility later earns its place.

## 8. Testing

- **Primitive layer** (`Pawl.JsonSpec`): the ported scrod parse/render cases,
  plus canonical-render determinism.
- **Codec** (`Pawl.CodecSpec`): P1 and P2 over `allPrintings` (a QuickCheck-style
  `forall c in allPrintings` HUnit sweep — real cards, per
  `tests-prefer-real-cards`; the pool *is* the fixture set). Per-type unit cases
  for the tagged-sum trap: `Quantity.ManaValue` round-trips as a nullary tagged
  object and `Quantity.Literal n` as a tagged object with a numeric `value` —
  never a bare number. (`Star`/`*` is the design rationale for the discipline,
  not yet a `Quantity` constructor, so it is not a live test case.)
- **Files** (`Pawl.CardsSpec` or alongside): P3 (each `data/cards/*.json`
  re-parses to its compiled card), byte-stability (re-render equals committed
  bytes), slug uniqueness.
- **Relocation**: the existing suites keep passing under the qualifier rename;
  `Pawl.Card`'s classification tests stay put.
- **Benchmark**: builds and runs `IO`-loading its cards (a smoke run in CI, if
  the benchmark is exercised there).

## 9. Risk

The one genuine unknown is the **`Lift` mechanism** for the TH shim (`Map`/`Set`
fields may lack `containers`-provided `Lift` on GHC 9.14). It is explicitly *not*
a concern that blocks the design — the fallback (hand-written lifting for the few
container-bearing types, or splicing a compile-time-validated JSON string) is
mechanical, and the plan settles it under TDD. Everything else in M3.5 is
mechanical volume (one codec pair per type), which is the milestone's nature: it
is a representation change, and its risk is tedium, not architecture.
