# M4.5 — Closing the closed-half gaps (umbrella spec)

*Design pass 2026-07-20, at M4h's completion (all of M4 done). This is an
**umbrella** spec: it fixes the milestone's shape — thesis, phase decomposition,
dependency ordering, per-phase gate card + axis + falsifier, deferred backlog,
exit criterion, and hand-off to M5. **Each phase gets its own detailed spec and
plan under `docs/superpowers/{specs,plans}/` when it is next up**, exactly as
M4a–M4h each did under the "M4" umbrella. Nothing here is implementable as-is;
it is the map the phase specs are derived from.*

## 0. Why this milestone exists

M4 built the effect-DSL **seams** — the open half (design.md §1) can now grow
forever: new opcodes land as M4-tail vocabulary on machinery that already exists.
But the `docs/mtgish-gap-census.md` analysis, written at M4's completion, found
that the **closed-half classification axes those effects hang off are still
incomplete**. Concretely (census §3, baseline table §2):

- Whole **layers are blank**: layer 1 (copy), layer 2 (control — `Object` has no
  `controller` field at all), layer 5 (color), layer 7 characteristic-defined P/T.
- There is **no player-scoped continuous-effect axis**: `ContinuousEffect` /
  `Modification` / `Affected` are object-only, and `Player` carries only `life` +
  `status`. ~250 mtgish `PlayerEffect` variants (skip steps, can't-cast, extra
  lands, cost modification, max hand size) have nowhere to live.
- The **replacement engine is wired for 2 of ~40 base events**:
  `ReplacementEffect` and `Prevention` each have a single card-specific
  constructor.
- The **targeting, duration, and cost enums grow one hand-carved variant per
  card** (`TargetSpec` is up to 8; M4g's `WallTarget` is the tell).
- Several small **player-state subsystems** (poison, energy, monarch, emblems…)
  and the **Command zone** are absent.

M5's "nightmares" (design.md §3: 723 Word of Command, 727 Karn restart, 729
Shahrazad subgames, 732/733) sit *on top of* these axes. Specifying M5 while the
axes are blank re-introduces exactly the fusion/rewrite risk the project is
sequenced to retire (design.md §7 risk register; §2.3/§2.4 "a hardcoded
assumption is a rewrite"). **M4.5 finishes the finite thing** — design.md §1: the
closed half genuinely *can* be completed — so M5 and the M4-tail vocabulary land
on solid axes.

This milestone is numbered **`.5`** deliberately, exactly as M3.5 was: an
interstitial between M4 and M5 that does **not** renumber M5–M7, which are cited
by number throughout the design doc.

## 1. Scope

**In scope** — the twelve closed-half **GAP** axes the census ranked (§4), grouped
into five clusters and ~eleven phases (§3 below). Each is a *classification /
axis*, not open-half vocabulary.

**Out of scope, deferred to backlog** (§4) — axes that ride the substrate the
phases build, plus the design.md §6 out-of-scope set (unchanged).

**Not in this milestone by construction** — the M4-tail *vocabulary* (new opcodes,
new trigger conditions, new counter names, layer-4 type breadth, cost instances):
these are **VOCAB** (census §5), grow forever on the seams M4 and M4.5 build, and
are tracked by opcode breadth (§4 of design.md), never by this spec.

### The definition-of-done for each phase (design.md §4 corollary)

A phase is **not done** until its axis has (a) a classification in the type system
and (b) a **real, recognizable gate card** exercised in a *gameplay-level* test —
a scenario that casts/resolves through the stack and asserts on game state, not a
unit test of an executor in isolation. A **labeled synthetic crutch with a
documented expiry** naming the card that retires it is legitimate *only* when a
real card would drag in something not yet built (the `Landform` /
synthetic-deathtrampler pattern). The gate card is how each phase proves the
engine **does** the right thing; the round-trip proves only that a card **says**
it (design.md §4, the central trap).

## 2. The two invariants every phase honors

These outrank the phase plan (CLAUDE.md, "Executing a plan"):

1. **The rules core reads a *classification*, never an effect's identity.** Every
   new axis this milestone adds — `PlayerEffect`, the would-*event* replacement
   vocabulary, the target-filter criterion language, the new layer operations — is
   a classification the closed half consults. `Pawl.Resolve` stays the sole home
   of `case effect of`; `Pawl.Event` the sole home of
   `case … ReplacementEffect / TriggerCondition`; `Pawl.Projection` the sole home
   of `case … Modification`. A new axis gets a new sole-casing home on the same
   pattern.
2. **The engine makes no choices.** CR 616 replacement ordering (P5),
   alternative-cost selection (P8), and copy-value / copiable picks (P2) are
   **prompts**. Any elided prompt (indistinguishable options only) carries a named
   expiry naming the card that kills the elision.

## 3. The phases

falsifies its naive implementation** (the M2/M3/M4 discipline). Gate cards are
**candidates** — each phase's own spec re-derives its exact gate from real cards
and `rules.txt` when written. **Every CR number below is marked *(verify)*** and
must be checked against `docs/rules.txt` before it drives code (CLAUDE.md: never
trust recalled Magic rules; the census marks the same numbers unverified).

### Notes the phase specs must not lose

- **GAP-Co is split across two phases — both now closed.** Cost *modification*
  (reduction/increase — Thalia, cost reducers) is a species of player-scoped
  continuous effect and folded into **P7**. Cost *payment generalization*
  (pay-life, sacrifice-N/type, discard-as-cost, exile-from-zone) plus the
  alternative-cost seam (flashback/overload) was **P8**. They are different axes:
  P7 closed the modification half, P8 the payment half.
- **The census's §3.2 misplaces turn-structure skips, and P7 did not follow it.**
  `docs/mtgish-gap-census.md` §3.2 lists `SkipsUntapStep`, `SkipsDrawStep`,
  `SkipsMainPhase`, `SkipsCombatPhase` and `SkipsUpkeepStep` under GAP-P's
  `PlayerEffect` heading. They do **not** belong on that axis: **CR 614.1b** —
  "effects that use the word 'skip' are replacement effects" — puts them on
  **P5's** `ReplacementEffect` carrier, replacing a step/phase/turn event with
  nothing. What is actually missing is on the replacement side: there is no
  "would begin a step/phase/turn" event to replace. Filed as issue #98 so a later
  phase does not build a `SkipsDrawStep` on the wrong carrier. Unaffected:
  `Pawl.Engine.skipsDraw` (CR 103.7a, the starting player's first draw step) is a
  **turn-based rule**, not an effect, and stays a plain predicate in `Engine`.
- **P3b revives M4a's deferred numeric tower.** Characteristic-defined P/T
  (Tarmogoyf `*/1+*`) needs `Quantity.Star` (characteristic-defining) and a
  `Count`-shaped quantity, both shape-only since M4a. P3b is where they cash. Relate
  to git-bug `c7a0077` (generalize the reserved X slot to `Quantity.Bound
  SlotName`) if a counting quantity needs a binding. **Landed answer: it did
  not.** Neither `Count CardTypesInAllGraveyards` (Tarmogoyf) nor
  `Count CardsInYourHand` (Inner Calm, Outer Strength) needed a binding slot —
  both read zone membership and printed card types directly — so `c7a0077`
  stays open, unretired by this phase (see §6).
- **P3b does *not* reopen P3a's CR 613.3 CDA-vs-timestamp precedence question.**
  P3a seeds devoid rather than folding it as a layer-5 CDA, argued sound because
  devoid is a *constant* CDA (a copy snapshot recomputes the same constant — see
  the P3a spec §2.2). Tarmogoyf's characteristic-defining P/T is a *dynamic* CDA
  (it reads the graveyards, which change over time); seeding it would freeze a
  Clone's P/T into `Binding.copy` at entry instead of recomputing (CR 707.2
  violation). So **P3b must fold its CDA in-place at the existing
  `Layer.CharacteristicPT` (7a)**, not at the seed, and needs no precedence key.
  **P3b does inherit** layer **7d P/T switching** (Twisted Image), which is its
  neighbourhood, not colour's — it stayed out of P3a by construction (P3a spec
  §7).
- **P5 subsumes git-bug `6afb561`.** The census (§3.1) is explicit: that bug is the
  replacement seam's *ordering/choice* facet (CR 616 + choice-bearing replacements),
  GAP-R is its *event-coverage* facet; together they are the full story. P5 owns
  both — the monadic path is what makes choice-bearing replacements and CR 616
  ordering expressible.
- **P4 is a substrate, and it gated P6 and P7 — landed, edge discharged.** The
  turn-scoped event history it adds to `GameState` (`events` plus per-consumer
  watermarks; both drain queues removed) is what event-relative durations (P6)
  and per-turn restrictions ("first time each turn", Rule of Law's spell count,
  P7) both read. It was built before its consumers. This was the third "event
  log" customer the design has recorded (M1b deathtouch note, M2b Moraug note,
  the single-pass SBA debt) — second-customer-not-new-problem. **P4 gates its
  readers by mechanism, not by vocabulary**: the log records only what its gate
  cards need, and each later phase adds the event kind it reads (`SpellCast` at
  **P7**).
- **P1 is deep, not merely a layer op.** `Object` has only `owner` today; layer-2
  control has nowhere to live until a `controller` field exists, and that field is
  read by every "you control" / APNAP / combat / priority site. It is a pervasive
  structural change — cheaper now than retrofitted (§2.3/§2.4). Player-control
  (Mindslaver, `GameState.pendingControl`, CR 723, M3g) is a **different** mechanism
  and does **not** cover Control Magic / Threaten.
- **P2 is the M4.5 go/no-go.** design.md §5 names the layer system as the canary and
  layer 1 is blank. If the immutable-base / projected-fold architecture is going to
  break, it breaks on copy (copiable values computed before other layers, self-
  reference). Front-loaded so the verdict arrives early, the M3 a→b→c→d principle.
- **Poison/energy force the player-counter substrate (P10).** The ~150 counter
  *names* are VOCAB (census §3.6); the structural gap is counters living on
  *players* (`Player` has no counter map) and the counter→layer-6 path (ability-
  granting counters feed the ability system, not just P/T). Poison also adds the
  loss-at-10 SBA.

## 4. Ordering, and what is deferred

**Recommended linear order: P1 → P11 as numbered.** Driven by
*substrate-before-consumer* and *risk-first* (design.md's own sequencing):

- **P1 first** — `Object.controller` is the most *pervasive* new field; retrofitting
  it later is a rewrite.
- **P2 (copy) is the go/no-go** — front-loaded per §5; leans on P1's controller field.
- **P3a and P3b** mop up the small layer ops while the projection is fresh — split
  per §7 into color (P3a, landed) and characteristic-defined P/T (P3b, landed),
  one axis each. **Both are now landed, and Cluster 1 (layer-system completion)
  is done**: layers 1 (P2), 2 (P1), 3 (M3d), 4 (M3c), 5 (P3a), 6 (M3b) and
  7a/7b/7c/7d (P3b) all have producers.
- **P4 (event substrate) is landed**, opening Cluster 2: one turn-scoped event
  log with last-known-information snapshots, state (603.8) and delayed (603.7)
  triggers, the intervening "if", and the CR 603.3b ordering prompt.
- **P5 (monadic replacement / CR 616) is landed** — the second real bet; it broke
  the pure single-fold assumption git-bug `6afb561` documented, closing Cluster
  2's second phase. Gate cards: Doubling Season + Hardened Scales/Corpsejack
  Menace, plus Clone + Primal Plasma (CR 616.2, unanticipated by this umbrella).
- **P6 (conditional & event durations) is landed**, closing GAP-D: a stored
  duration now has a beginning (CR 611.2b) as well as an end. Gate cards:
  Master Thief + Hag of Inner Weakness. It did **not** land as a reader of the
  event log — the turn handoff is the event (see §3's P6 row) — though it does
  read P4's `stateHolds`.
- **P7 (player continuous effects, restrictions & cost modification) is
  landed**, closing GAP-P and the *modification* half of GAP-Co, and with them
  **the whole of Cluster 3**. Gate cards: Rule of Law, Thalia, Sapphire
  Medallion, Reliquary Tower, Silence. It can express per-turn restrictions only
  because P4 exists — Rule of Law's count is a fold over P4's whole turn log.
  It did **not** land inside the layer system: CR 613.10/613.11 put this axis
  after the layers, not in them (see §3's P7 row).
- **P8 (cost generalization + alternative costs) is landed**, closing the
  *payment* half of GAP-Co and with it the whole of GAP-Co (P7 closed the
  modification half). Gate cards: Greed, Village Rites, Fireblast. One `Cost`
  serves spells and activated abilities, the CR 118.6 unpayable/`{0}`
  distinction is carried in the type, and printed additional and alternative
  costs live on `Card`. Ability costs are deliberately **not** routed through
  `Cost.total` (see §3's P8 row and #90).

**Reorderable — no hard dependency:** with Cluster 3 closed and **P8** (costs)
landed, **P9** (filter language), **P10** (player counters) and **P11** (command
zone) remain, none blocking another. **P9 is high-value-early** (every later gate
card gets cleaner targets), so pulling it up to roughly P4's position is a
legitimate call. **P10 / P11** are last by *leverage*, not dependency.

**Hard dependency edges** (the only ones): `P1 → P2` (**discharged** — both
landed); `P4 → {P6, P7}` (**discharged** — P4 landed, so neither reader is
blocked); `P10 → backlog subsystems`; `P11 Command → emblems`;
`P2 copy → backlog face-down`.

**Deferred to backlog** — ride the substrate the phases build; each becomes a
mini-section when a card needs it (census §6.4). **Not phases in M4.5:**

- **Face-down** (morph / disguise / manifest / cloak) — rides P2 copy + a face-down
  *status* (not a zone; census §3.5).
- **Phasing** — its own status mechanism (phased-out is a status, not a zone); rare;
  backlog.
- **Remaining GAP-S subsystems** — the Ring / Ring-bearer, venture / dungeon,
  initiative / undercity, speed (Aetherdrift), experience / rad counters — all ride
  P10's player-counter substrate and P4's triggers.
- **design.md §6 out-of-scope, unchanged** — ante, dexterity, draft / Conspiracy
  (second VM), un-set social / art-content, contraptions.

## 5. Exit criterion and hand-off

**Exit criterion.** Every closed-half axis the census flagged **GAP** (§3's eleven
phases) has (a) a classification / axis in the type system and (b) a real gate card
with a passing gameplay-level test. At that point the closed half is "finished" in
the design.md §1 sense for the flagged surface. The card-count metric stays
deferred; breadth (opcode/axis coverage) remains the progress signal (design.md §4).

**Hand-off to M5.** With controller (P1), copy (P2), the monadic event/replacement
substrate (P4/P5), and player-control-as-continuous-effect (P7) in place, M5's 723
(Word of Command), 727 (Karn restart), and 729 (subgames) sit on complete axes
instead of forcing them mid-nightmare. M5 remains the design.md §3 milestone,
unchanged in content.

## 7. Process

Each phase is brainstormed → specced → planned → implemented on its own, in the
recommended order (§4), following the standard flow (`superpowers:writing-plans`
for the plan, TDD per CLAUDE.md, one small complete commit per plan task on
`main`). This umbrella is the source the per-phase specs derive their gate card,
axis, falsifier, CR sections, and dependencies from; a phase spec that departs from
the umbrella (a better gate card, a merged/split axis) updates this file so the map
stays true — the same "stop and say so if the plan looks wrong" discipline the
milestone plans already carry.
